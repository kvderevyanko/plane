# Политика расхода токенов агентами LR1600

## Цель

Получать проверяемые инженерные решения без повторного чтения одних и тех же
артефактов, fan-out нескольких ролей и неявного перехода на дорогую модель.
Эта политика не ослабляет требования к прочности, центровке, авионике или
производственной готовности.

## Зафиксированные профили

| Роль | Модель | Reasoning effort |
| --- | --- | --- |
| `aircraft-lead` | `gpt-5.6-sol` | `high` |
| `aero-analyst` | `gpt-5.6-terra` | `high` |
| `structures-manufacturing` | `gpt-5.6-terra` | `high` |
| `avionics-autopilot` | `gpt-5.6-terra` | `high` |
| `independent-reviewer` | `gpt-5.6-sol` | `high` |
| `cad-laser-engineer` | `gpt-5.6-terra` | `medium` |

`gpt-5.6` не использовать: это алиас GPT-5.6 Sol. Sol разрешён только двум
редким gatekeeper-ролям: `aircraft-lead` для существенного системного решения
и `independent-reviewer` для обязательного независимого ревью. GPT-5.6 Terra
— ceiling остальных специализированных ролей; GPT-5.6 Luna не используется
для инженерного решения, расчёта или ревью. `high` остаётся профилем критичных
ролей, поэтому экономия достигается не ослаблением рассуждения, а запуском
роли только когда без инженерной интерпретации действительно нельзя обойтись.

## Порядок работы

1. Сначала выполнить детерминированные проверки: `./tools/check-agent-profiles.sh`
   и релевантные существующие тесты или генераторы. Они не требуют LLM.
2. Если проверка отвечает на вопрос, не запускать специалиста.
3. Для одной ограниченной подзадачи назначать одного owning-специалиста. Не
   запускать несколько ролей для повторного чтения тех же исходных файлов.
4. В поручении передавать только пути к source-of-truth, конкретный вопрос и
   критерии результата; не вставлять в контекст полные логи, generated-файлы
   или уже проверенные расчёты.
5. Объединять связанные вопросы одной дисциплины в один запрос. Findings,
   входные данные и вывод сохранять в `docs/`, чтобы их не пересчитывать.
6. `independent-reviewer` запускать после готового diff или артефактов и только
   в обязательных контрольных точках из `AGENTS.md`; не использовать как
   предварительный второй opinion без нового факта.
7. `aircraft-lead` привлекать только при реальном конфликте дисциплин или при
   решении, которое меняет массу, CG, геометрию, нагрузки либо систему в целом.

## Автоматический guard

`scripts/check_agent_profiles.py` проверяет, что каждый из шести TOML-файлов
существует, синтаксически корректен, явно задаёт утверждённую модель и уровень
reasoning. Проверка включена в `pytest`; вручную она запускается
`./tools/check-agent-profiles.sh`.

Перед выпуском деталей дополнительно обязательны все релевантные CAD и
инженерные тесты. Успешный policy check не заменяет независимое ревью или
proof-test.
